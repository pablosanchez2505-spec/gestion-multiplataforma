src/app/core/interceptors/auth-error.interceptor.ts

authErrorInterceptor
Type : HttpInterceptorFn
Default value : (req, next) => { const auth = inject(AuthService); const router = inject(Router); const toastCtrl = inject(ToastController); const notify = async (message: string, color: 'warning' | 'danger') => { const toast = await toastCtrl.create({ message, color, duration: 2500, position: 'top' }); await toast.present(); }; const expireSession = () => { auth.logout(router.url); void notify('Tu sesión ha caducado. Vuelve a iniciar sesión.', 'warning'); }; return next(req).pipe( catchError((error: unknown) => { // Login/refresh gestionan sus propios errores (credenciales incorrectas, etc.) if (!(error instanceof HttpErrorResponse) || req.context.get(SKIP_AUTH)) { return throwError(() => error); } if (error.status === 401) { // Ya se reintentó con un token recién renovado y sigue fallando → fin de sesión if (req.context.get(RETRIED_AFTER_REFRESH)) { expireSession(); return throwError(() => error); } return auth.refreshAccessToken().pipe( switchMap(() => next(markAsRetried(req))), catchError((retryError: unknown) => { // Si el error viene del refresh (no del reintento), cerramos sesión aquí if (!(retryError instanceof HttpErrorResponse) || retryError.url?.includes('/auth/refresh')) { expireSession(); } return throwError(() => retryError); }), ); } if (error.status === 403 && !req.context.get(SKIP_FORBIDDEN_REDIRECT)) { void notify('No tienes permisos para realizar esta acción.', 'danger'); router.navigate(['/forbidden']); } return throwError(() => error); }), ); }

Interceptor de ERRORES DE SESIÓN (respuesta entrante). Va el PRIMERO en la cadena, así al reintentar con next() la petición vuelve a pasar por authInterceptor y sale con el token nuevo.

401 Unauthorized → token caducado/inválido: 1. Pide un access token nuevo con el refresh token (una sola vez). 2. Reintenta la petición original. 3. Si el refresh falla → cierra sesión y manda al login con returnUrl. 403 Forbidden → autenticado pero sin permiso → pantalla /forbidden.

src/app/core/interceptors/auth.interceptor.ts

authInterceptor
Type : HttpInterceptorFn
Default value : (req, next) => { const isApiCall = req.url.startsWith(environment.apiUrl); if (!isApiCall || req.context.get(SKIP_AUTH)) { return next(req); } const token = inject(AuthService).getAccessToken(); if (!token) { return next(req); } return next(req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })); }

Interceptor de AUTENTICACIÓN (petición saliente). Añade Authorization: Bearer <token> a todas las llamadas a nuestra API.

  • No toca peticiones a terceros (no filtramos el token a otros dominios).
  • No toca login/refresh (marcadas con SKIP_AUTH). Los servicios de datos no saben nada de tokens: solo hacen http.get(...).

src/main.ts

interceptors
Type : HttpInterceptorFn[]
Default value : [authErrorInterceptor, authInterceptor]

Cadena de interceptores (el orden importa): petición → authErrorInterceptor → authInterceptor → [mockBackend | red] respuesta ← authErrorInterceptor ← authInterceptor ← [mockBackend | red]

  1. authErrorInterceptor va primero para que, al reintentar tras el refresh, la petición vuelva a pasar por authInterceptor y salga con el token nuevo.
  2. authInterceptor añade el Bearer.
  3. mockBackendInterceptor (solo sin API real) hace de servidor.
